下面是“个人知识库（工作文件）”功能模块的评审版设计，结合你当前项目已有能力（OCR、结构化切分、Qdrant 向量库、BM25 混合检索、process_id 分组等）。先给功能设计与模块边界，便于你评审后再落地实现。

目标与范围

目标：把工作中的多种文件（PDF/Word/Excel/图片/邮件导出等）快速变成可检索、可问答、可引用的个人知识库。
范围：本地文件为主，支持增量更新、按项目/主题分库管理，支持问答与引用出处。
非目标：不做复杂协作权限系统或大型企业级知识中台（先定位个人/小团队可用）。
模块清单（功能边界）

素材接入模块（Ingestion）
文件夹导入、拖拽导入、定期扫描（watcher）。
支持多库管理（kb_id），同一文件可被多个库引用。
文件去重（hash）与增量更新（mtime + hash）。
文档解析模块（Parsing）
文本抽取（pdf/docx/xlsx/csv/txt）。
OCR（图片/PDF 图片页），保留页码与区域信息。
语言检测、乱码/空白页过滤。
结构化/切分模块（Structuring & Chunking）
按标题/段落/章节切分，保留层级路径。
对表格/清单类文件采用按行或项目切分。
生成摘要标题（可选）用于检索提示。
索引模块（Indexing）
向量索引（Qdrant）+ 关键词索引（BM25）。
维护索引清单（manifest），支持重建与部分重建。
索引版本号、参数快照（chunk_size、overlap、embedding_model）。
检索模块（Retrieval）
混合检索（BM25 + 向量）+ 过滤条件（库、标签、时间、文件类型）。
去重与重排序，输出引用片段。
问答生成模块（Answering）
基于检索结果拼接上下文。
强制引用来源（文件名 + 页码/段落）。
“不知道”保护策略（未命中则拒答）。
知识库管理模块（KB Management）
库创建/删除/重命名、标签体系、文档归档状态。
手动标注（重点、过期、可信度）。
日志与统计模块（Observability）
记录每次检索命中率、耗时、token 消耗。
OCR 失败、解析失败的可视化清单。
安全与隐私（Security）
本地存储为主；可选加密索引文件。
查询日志脱敏（路径/文件名可配置隐藏）。
核心数据模型（建议）

KnowledgeBase
kb_id, name, created_at, tags, description
Document
doc_id, kb_id, source_path, file_hash, file_type, created_at, updated_at, tags
Chunk
chunk_id, doc_id, text, page, section_path, tokens, checksum
IndexManifest
kb_id, embedding_model, chunk_params, doc_count, chunk_count, updated_at
关键流程

入库流程（一次性或增量）
扫描文件 → 解析/OCR → 结构化切分 → 生成元数据 → 索引更新
查询流程
用户问题 → 过滤条件 → 混合检索 → 重排 → 生成回答 → 产出引用
检索策略建议（结合现有实现）

默认混合检索（BM25 + 向量），alpha 可调。
对表格/清单类文档优先 BM25，提高精确命中。
支持按库/标签/时间过滤，避免“跨项目混答”。
目录结构建议（保持现有习惯）

data/source/<kb_id>/... 原始文件
data/processed/<kb_id>/... 解析文本
index/<kb_id>/... 向量索引与 BM25 索引
data/log/<kb_id>/... 日志与统计
MVP 版本建议

支持：多文件导入、OCR、混合检索、引用回答、kb_id 多库隔离。
暂缓：复杂 UI、权限管理、在线协作、复杂图谱。
待确认问题（评审用）

你的知识库规模预计多少（文件量/页数）？这决定索引策略和成本控制。
是否需要“多库”功能（不同项目/主题分开）？
是否需要对某些文件做加密或不入库（敏感数据）？
查询偏好：更重“精确定位条款”还是“概括性回答”？
