Attachment 命中“中标通知书.png”的路径逻辑在这几处拼起来：

读取源文件 → 生成原始 docs
process_sources 会递归 data/source/<process_id>/...，对每个文件做 OCR/抽取，doc 的 metadata.source 是原始文件路径，metadata.source_type 先被设置成“文件后缀”。
代码：source_processing.py, document_utils.py
结构化成“表单/附件”
_build_contract_documents 会根据路径里的目录名判断是否“表单/附件”（form/forms/表单 或 attachment/attachments/附件），然后把附件拆成段落并打上 metadata.source_type="attachment"、metadata.filename、metadata.process_id。
代码：rag_contract_utils.py
选择“合同附件文件名”（关键点）
ContractAttachmentSelector 把所有附件按“文件名”分组，抽取每个文件的“头部/尾部”文本，然后按一组合同特征打分（文件名包含“合同”、头部出现甲乙方/合同字段、条款编号、尾部签章等；文件名/内容命中排除词会扣分或直接剔除）。
没有最低分阈值：只要不被排除，就会进候选，即使得分是 0 或负数也会被选为 top_k（默认 1）。
代码：contract_attachment_selector.py
选中文件后会“强行缩小附件范围”
在 rag-contract.py，如果 selector 选出了 contract_names，会立即把 attachment_docs 过滤为“仅该文件名”的 docs，并设置 attachment_scope = SourceScope(names=...)。
后续检索只在这个文件里进行（向量库也只索引它）。
代码：rag-contract.py
Retrieval scope: files=... 的来源
run_extraction 里会打印 scope，并用 _filter_docs_by_scope 统计 Scope files。
_filter_docs_by_scope 仅用 基名 (Path(source).name) 精确匹配 scope.names，大小写敏感。
代码：rag_contract_service.py, rag_contract_utils.py
