# 文件筛选逻辑 PRD

## 1. 背景与目标
“文件筛选”用于在问答前快速限定检索范围，避免全库混杂结果。  
当用户输入问题时，系统根据“问题文本 + 已入库文件清单”自动推荐可过滤的文件，并支持多选。

目标：
- 基于问题自动给出“可选文件”列表（不要求用户输入文件名）。
- 用户可点击选择多个文件，作为检索过滤条件。
- 推荐逻辑可解释、可调优、可扩展。

## 2. 交互位置
- 左侧「文件筛选」区域：
  - **已选文件**（显示当前已选的文件，多选、可取消）
  - **可选文件**（系统推荐/候选）

## 3. 输入与数据来源
### 输入
- 用户问题（question）
- 选中的 KB（kb_id，可多选）

### 数据来源
- `data/manifest/<kb_id>/files.json`
  - 过滤条件：`status == indexed` 且 `source_deleted == false`
  - 取值字段：`abs_path` 的文件名（basename）
  - 对同名文件，保留 `updated_at` 最新的记录

## 4. 推荐逻辑（核心）
### 4.1 预处理
- 若未选择 KB：使用默认 KB（第一个有效 KB）。
- 若问题为空：不做推荐，提示“输入问题后自动推荐可过滤的文件名”。

### 4.2 Token 抽取规则
从问题中抽取用于匹配的 token：
- 英文/数字片段（长度 ≥ 2）。
- 中文片段拆分为 2~3 字 n-gram（提高“防病毒”等词的命中率）。
- 月份表达：`2月` / `2月份` / `12月` / `12月份`（自动加入 token）。
- 文件名显式出现（如 `xxx.xlsx`）视为强命中。

### 4.3 匹配打分规则
对每个文件名计算得分：
- **文件名完整命中**（如问题中出现 `bug反馈表.xlsx`）：+30
- **命中文件名主干**（去扩展名，如 `bug反馈表`）：+20
- **token 命中**：
  - token 命中文件名主干：+3
  - token 命中文件名全名：+1
- **显式文件名命中**（问题中出现含后缀的文件名）：额外 +50

### 4.4 排序与输出
1) 只保留 **得分 > 0** 的文件  
2) 排序规则：`score` 降序，`updated_at` 升序，`name` 字典序  
3) 输出 Top N（默认 8）

### 4.5 无命中兜底
若全部文件得分为 0：  
输出“最近更新文件”Top N，并显示提示：  
**“未识别到文件名，以下为最近文件”**

## 5. 多选与已选文件展示
- 可选文件点击即加入“已选文件”列表。
- 再次点击同名文件可取消选择。
- 已选文件列表以 pill 展示，支持点击移除。
- 已选文件最终提交为过滤条件（多选，逗号分隔）。

## 6. 边界与异常
- KB 不存在或无文件：提示“暂无可用文件”。
- 问题为空：不展示推荐列表，仅提示输入问题。
- 仅凭文件名推荐，不依赖内容召回（避免性能开销）。

## 7. 可调参数
- Top N 推荐数量（默认 8）。
- token 长度（中文 n-gram 2~3）。
- 权重分值（命中权重可调整）。

## 8. 示例
- 问题：**“总结下2月防病毒”**  
  - token 包含：`2月`、`2月份`、`防病毒`  
  - 推荐文件：`2月份防病毒报告.doc`
