# 知识库匹配问题：日期检索无效解决方案（A+B）

版本：v1.0
日期：2026-01-24

## 1. 背景与问题
当前 Excel（如 bug反馈表.xlsx）在入库时被当作“整块文本”切分，检索时存在：
- 用户问题包含“25年9月/2025-09”等日期表达，BM25 与向量检索难以稳定命中对应行。
- 即使知识库中存在对应日期记录，检索候选不一定包含该行，导致回答“无法从知识库中找到依据”。

## 2. 目标（P0.1）
- 让“按月份/日期”类问题稳定命中表格中的对应行。
- 不引入“兜底拼接回答”，而是通过索引与文本标准化提升召回。
- 对既有流程影响最小，逻辑清晰、可回滚。

## 3. 方案概述
本方案采用 A + B 两步：

A. Excel 行级切分 + 行级索引
- 将 Excel 每一行转成独立 Document/Chunk，保留 sheet、row、date 等元数据。
- 让检索粒度从“整表块”变为“单行”，显著提升日期类查询的召回准确性。

B. 日期标准化（索引前）
- 在入库时，为文本追加标准化日期 token（例如 DATE=2025-09），使 BM25 及向量更容易匹配。
- 对“25年9月/2025-09/2025年9月”的多种表达提供统一索引信号。

## 4. 方案 A：Excel 行级切分 + 行级索引
### 4.1 行级 Document 结构
每行变成一个 Document，核心字段：
- page_content：拼接后的“行文本”（保留原列顺序，用 TAB 分隔）
- metadata：
  - source：原始文件路径
  - source_type：xlsx
  - sheet：Sheet 名
  - row：行号（从 1 开始，排除表头需记录）
  - doc_id：相对路径
  - chunk_id：行内序号

### 4.2 表头处理建议
- 第一行通常为表头；可配置：
  - 默认将首行作为表头，不入库；
  - 或入库但增加 metadata: is_header=true 以便检索时过滤。

### 4.3 改动点
- `src/util/extractors.py`
  - 新增：`_extract_excel_rows(path) -> list[dict]`
  - 输出每行结构：`{"sheet": name, "row": n, "cells": [...], "text": "..."}`
- `src/kb/parse.py` / `src/util/document_extractor.py`
  - 对 xls/xlsx 走行级解析并生成 Document 列表
- `src/kb/chunk.py`
  - 对表格类 Document 禁止再次长度切分（直接 passthrough）

## 5. 方案 B：日期标准化（索引前追加）
### 5.1 标准化规则
识别如下日期表达，追加统一 token：
- `YYYY-MM-DD`、`YYYY/MM/DD`、`YYYY.MM.DD`
- `YYYY-MM-DD HH:MM:SS`（含时间）
- `YYYY-M-D`、`YYYY/M/D`（月/日单数字）
- `YYYY年M月D日`
- `YYYY-MM`、`YYYY/MM`、`YYYY年M月`
- `YY年M月`（转换成 YYYY-MM）
- `YY/MM/DD`、`YY-M-D`（两位年）
- `YYYYMMDD`、`YYYYMM`（无分隔）
- Excel 数字日期（例如 45123 / 45123.0）：按 Excel 日期基准转换

追加示例：
原行：
`2025-09-01 00:00:00 张三 无法提交下个节点流程 ...`
追加后：
`2025-09-01 00:00:00 李四 无法提交下个节点流程 ...  [DATE=2025-09] [DATE=2025-09-01]`

### 5.2 改动点
- `src/kb/chunk.py` 或 `src/kb/parse.py`
  - 在生成 Document 前，对 page_content 做日期正则识别并追加标准化 token。

## 6. 兼容性与回滚
- 方案 A 只影响 Excel/XLSX 文档，不影响其他类型。
- 方案 B 对所有文本可用，但可仅在表格类文档中启用。
- 回滚方式：
  - 关闭“行级切分”（恢复整表文本）
  - 关闭“日期标准化”追加

## 7. 验收标准
- 输入问题：
  - “bug反馈表里面，25年9月份有哪些记录？”
- 期望：
  - Top-K 检索命中包含 2025-09 的行；
  - LLM 输出对应记录（无需兜底逻辑）。

## 8. 实施步骤（建议）
1) 实现 Excel 行级解析（extractors）并产出 Document。
2) 对行级 Document 增加 date 标准化 token。
3) 重新 ingest 目标 KB。
4) 用测试问题回归验证。

## 9. 风险与注意事项
- 行级切分会显著增加 chunk 数量（索引体积增大）。
- 过多日期 token 可能带来噪声，但对月份查询有明显收益。
- 对带合并单元格或特殊格式 Excel，解析需容错。
