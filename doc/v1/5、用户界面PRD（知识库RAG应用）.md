# 5、用户界面 PRD（知识库 RAG 应用）

版本：v1.0
日期：2026-01-24

## 1. 背景
当前检索以命令行/接口为主，缺少完整可视化入口。需要覆盖：
- 知识库管理（新建/重命名/删除/状态）
- 入库与解析进度
- 检索与问答（含文件过滤与渐进式检索）

## 2. 目标
- 提供完整 RAG 应用页面：知识库列表、入库、检索、结果与引用
- 支持“全库检索 → 一键过滤”的渐进式体验
- 展示命中证据、来源文件与元数据（sheet/row/page）

## 2.1 技术方案（前端实现）
建议采用 FastAPI + Jinja2 + HTMX：
- 现有项目为 Python，服务端逻辑可直接复用
- HTMX 支持“搜索→过滤→更新结果”的局部刷新交互
- 无需复杂前端打包，上线/调试更快

## 3. 核心用户流程
1) 用户选择/创建 KB
2) 选择目录并启动入库（显示进度与清单）
3) 在检索页输入问题并发起全库检索
4) 系统展示结果与“可过滤项”
5) 用户点击过滤器或手动指定文件名
6) 系统仅基于该文件重新检索并展示结果

## 4. 信息架构
- 顶部：全局导航（KB 列表/入库/检索/日志）
- 左侧：上下文面板（KB 切换、过滤器）
- 右侧：结果区（回答 + 证据 + 原文）
- 底部：检索统计（Top‑K、耗时、召回来源）

## 5. 页面结构与组件
### 5.1 知识库列表页（KB Home）
- KB 列表（名称、文档数、更新时间）
- 新建/重命名/删除
- 进入 KB

### 5.2 入库页（Ingest）
- 目录选择（必须绝对路径）
- 入库状态（扫描数、已入库/未入库/错误）
- 查看清单（ingest_report）
- 可选：重新入库按钮

### 5.3 搜索页（Query）
- 搜索输入框（placeholder："请输入问题"）
- 查询按钮
- 高级参数：Top‑K / BM25 开关 / 时间范围

### 5.4 过滤器区域
- 文件名列表（Top 10）
- 文件类型筛选（xlsx/pdf/docx…）
- 路径层级过滤（按目录聚合）
- 时间范围（创建/修改时间）

### 5.5 结果区域（Answer + Evidence）
- 回答区域：
  - 最终回答
  - 引用列表（可点击跳转到证据片段）
- 证据列表：
  - 文本片段（高亮命中词）
  - 来源文件名、Sheet、Row（如适用）
  - Score、来源类型（vector/bm25/fusion）
- 展开查看全文（跳到解析文本）

## 6. 交互逻辑
- 默认全库检索
- 点击文件名过滤器后：
  - UI 展示“过滤中：xxx”标签
  - 仅该文件返回结果
- “清除过滤”按钮恢复全库检索
- 若过滤后无结果，提示“当前过滤无匹配，建议清除过滤”

## 7. 推荐交互（体验优化）
- 系统自动提示“是否仅搜索该文件？”
- 渐进式过滤：
  - 同屏显示“全库结果”与“该文件结果”对比

## 8. 数据与接口
- `GET /kb`：获取 KB 列表
- `POST /kb`：新建 KB（可选指定 root）
- `POST /ingest`：启动入库（root + kb_id）
- `GET /ingest/status`：入库状态与清单
- `POST /search`：检索（query + filters）
- `POST /search/filtered`：强过滤检索（query + file_name）

## 9. 验收标准
- 可以完成“全库检索 → 过滤到某文件”的流程
- UI 能展示过滤器推荐项
- 过滤后结果可读性强（含引用信息）
- 入库页能展示已入库/未入库/错误清单

## 10. 风险与注意事项
- 过滤器推荐可能误导（需提供“清除”入口）
- 结果片段过长时需折叠
- 大库场景需分页
