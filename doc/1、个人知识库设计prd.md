# 个人知识库（工作文件）PRD

版本：v1.0
日期：2026-01-23
作者：Codex

## 1. 背景与问题
- 工作文件分散在不同目录、格式不一（PDF/Word/Excel/图片/邮件导出）。
- 传统搜索只能按文件名或关键词，无法理解语义，难以快速定位答案与出处。
- 需要一个“本地优先、可增量、可引用”的个人知识库能力，支撑日常检索与问答。

## 2. 目标与非目标
### 2.1 目标
1. 将多种格式工作文件快速入库并可检索。
2. 支持语义问答，并强制给出引用来源（文件名 + 页码/段落）。
3. 支持增量更新与多库隔离（按项目/主题管理）。
4. 全流程可追踪（日志、统计、失败可回溯）。

### 2.2 非目标
- 不做复杂的企业权限体系与多人协作审批。
- 不提供在线编辑/协同写作能力。
- 不做大规模搜索平台（以个人/小团队规模为主）。

## 3. 术语与定义
- 知识库（KB）：一组被统一管理与检索的工作文件集合。
- 文档（Document）：一个物理文件及其解析产物。
- 片段（Chunk）：从文档切分得到的最小检索单元。
- 元数据（Metadata）：文档/片段的结构化信息（来源、页码、标签等）。
- 混合检索：向量检索 + 关键词检索（BM25）融合排序。

## 4. 用户画像与使用场景
### 4.1 用户画像
- 个人知识管理者：需要快速查找合同条款、工作流程、会议纪要等。
- 小团队负责人：需要在项目资料中快速定位关键结论与出处。

### 4.2 典型场景
1. “这份合同里违约金是多少？给出原文出处。”
2. “去年项目复盘中提到的风险清单是什么？”
3. “请汇总 2025 年度采购条款中付款条件，并引用来源。”

## 5. 需求范围（MVP 与后续）
### 5.1 MVP（必须）
- 多格式文件入库（PDF/Word/Excel/图片/txt）。
- OCR 能力（图片/PDF 扫描件）。
- 结构化切分与向量索引 + BM25。
- 语义问答与引用来源。
- 多库隔离与增量更新。
- 基础日志与统计。

### 5.2 后续增强（可选）
- UI 管理台与可视化检索界面。
- 自动标签与主题聚类。
- 访问控制与加密存储。
- 多人共享与权限协作。

## 6. 功能需求（详细）
### 6.1 素材接入（Ingestion）
**功能**
- 文件夹导入、拖拽导入、定期扫描（watcher）。
- 支持多库管理（kb_id），同一文件可被多个库引用。
- 文件去重（hash）与增量更新（mtime + hash）。

**输入/输出**
- 输入：必须是操作系统绝对路径（Win10 或 Linux 路径）指向的文件/目录；禁止指定项目内目录（避免复制大文件）。
- 输出：Document 记录 + 解析后的文本文件。

### 6.2 解析与 OCR（Parsing）
**功能**
- PDF/Word/Excel/txt 解析。
- 图片与扫描 PDF 使用 OCR。
- 保留页码、段落与位置。

**异常处理**
- 解析失败：标记失败状态并保留错误日志。
- OCR 超时：重试 1 次，失败记录。

### 6.3 结构化切分（Structuring & Chunking）
**功能**
- 按标题/章节/条款切分（优先结构化）。
- 无结构时按长度切分（chunk_size + overlap）。
- 对表格、清单类文档采用按行切分。

**参数**
- RAG_CHUNK_SIZE（默认 800）
- RAG_CHUNK_OVERLAP（默认 100）

**下一迭代增强（当前版本不做）**
- 以 token 计量切分阈值（替代字符计量），让 chunk 大小更稳定。
- 生成层级元数据（section_path / clause_id）用于精确定位与引用。
- 多粒度索引（段落级/条款级/章节级并存），按问题类型选择粒度。
- 表格行切分时拼接表头或转键值对，避免字段语义丢失。
- OCR 噪声清洗（页眉页脚/水印/重复行剔除）提升检索质量。

### 6.4 索引（Indexing）
**功能**
- 向量索引（Qdrant 本地或远端）。
- BM25 关键词索引。
- 维护 manifest（索引版本与参数快照）。

**增量策略**
- 新增文件：追加索引。
- 更新文件：删除旧索引并重建。
- 删除文件：标记并从索引清除。

### 6.5 检索（Retrieval）
**功能**
- 混合检索（向量 + BM25）。
- 支持过滤：kb_id、标签、时间范围、文件类型。
- 返回 Top-K 片段并去重排序。

**排序策略**
- 归一化后加权融合（alpha）。
- 可选 rerank（后续增强）。

### 6.6 问答（Answering）
**功能**
- 拼接检索上下文并调用 LLM。
- 强制引用来源（文件名 + 页码/段落）。
- 未命中时返回“无法从知识库中找到依据”。

### 6.7 知识库管理（KB Management）
- KB 创建/删除/重命名。
- 标签体系（项目/主题/保密等级）。
- 文档归档状态（active/archive）。

### 6.8 观察与统计（Observability）
- 记录：查询耗时、token 使用、命中率。
- 错误统计：OCR 失败、解析失败。
- 产出日志与可读报表（JSON/CSV）。

### 6.9 安全与隐私
- 默认本地存储；可选索引文件加密。
- 查询日志脱敏（路径/文件名可隐藏）。
- 支持敏感文件“仅解析不入库”。

## 8. 关键流程
### 8.1 入库流程
1. 扫描文件目录。
2. 解析/OCR。
3. 结构化切分。
4. 生成元数据与 manifest。
5. 向量索引与 BM25 索引更新。

**更新策略（增量）**
- 新增文件：解析并追加索引。
- 变更文件（mtime/hash 变化）：删除旧索引后重建该文档索引。
- 删除文件：仅标记“源文件已删除”，保留索引与解析产物；回答时注明“来源已删除”。

### 8.2 查询流程
1. 用户输入问题 + 过滤条件。
2. 混合检索并排序。
3. 生成回答并附引用。
4. 记录日志与统计。

## 9. 系统架构（逻辑）
- Ingestion/Parsing/Chunking
- Indexing（Qdrant + BM25）
- Retrieval + Answering
- KB 管理与监控

## 10. 目录与存储建议
- 原始文件：保留在用户指定的系统路径（Win10/Linux 绝对路径），不复制进项目目录。
- data/processed/<kb_id>/... 解析文本（由源文件生成，可重建）
- index/<kb_id>/... 向量索引与 BM25（可重建）
- data/log/<kb_id>/... 日志与统计
- data/manifest/<kb_id>/... 源文件清单与状态（记录源路径、hash、删除标记等）

**data/processed/<kb_id> 目录设计（建议）**
- manifest.json：处理清单（doc_id、source_path、hash、status、updated_at、error）
- docs/<doc_id>/raw.txt：抽取后的完整文本（可选）
- docs/<doc_id>/pages/page_0001.txt：按页文本（可选，便于引用）
- docs/<doc_id>/chunks.jsonl：切分后的片段（含 chunk_id、section_path、page、text）
- docs/<doc_id>/meta.json：文档元数据（标题、类型、页数、语言）
- ocr/<doc_id>/page_0001.json：OCR 结果原始输出（可选，便于回溯）

说明：
- doc_id 可用源路径 hash + 文件名生成，避免重名冲突。
- raw/pages/chunks/ocr 都可按需开关（默认保留 chunks + meta）。

**多源路径匹配策略（建议）**
- 不依赖目录层级对齐，使用 manifest 做“源路径 → 处理结果”的映射。
- source_path 统一存为规范化绝对路径（Win10/Linux）。
- doc_id 建议基于 kb_id + 规范化路径 + file_hash 生成，确保唯一性。
- 可选增加 root_id（源目录 ID），用于多路径归属：processed 按 `data/processed/<kb_id>/<root_id>/<doc_id>/...` 组织。

**路径与 KB 关系的配置化（可追溯）**
- 增加配置文件（如 `data/manifest/kb_paths.json`），显式维护“source_root_path → kb_id”的映射关系。
- 入库/扫描时优先读取该映射，确保同一路径始终归属同一 KB，便于追溯。
- 配置变更需要记录变更日志（时间、操作者、旧值/新值）。
- 规则：新增“文件”无需修改配置；仅当新增“源目录（source_root_path）”时才需要更新该映射（建议通过 CLI/管理界面操作，不手改文件）。

## 11. 非功能性要求
- 性能：单次查询 3-5 秒内返回（本地小规模）。
- 扩展性：支持 10k 级 chunk 的库。
- 稳定性：解析失败不影响整体流程。
- 可追踪：所有索引与查询行为可追溯。

## 12. 验收标准（MVP）
- 能成功入库 100+ 文件（含 PDF/Word/图片）。
- OCR 成功率 >= 90%（可人工抽检）。
- 支持问答并能引用出处。
- 支持增量更新（新增/修改/删除文件生效）。
- 查询耗时 <= 5s（本地样例库）。

## 13. 风险与假设
- OCR 质量依赖外部服务稳定性。
- 大型 Excel 表格可能导致切分质量下降。
- 语义检索效果依赖 embedding 模型质量。

## 14. 里程碑
- M1（1 周）：入库 + OCR + 解析流程稳定。
- M2（2 周）：索引与混合检索完成。
- M3（3 周）：问答与引用输出完成。
- M4（4 周）：统计报表与错误回溯。
